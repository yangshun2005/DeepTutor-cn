# DeepTutor v1.5.9 发布说明

**发布日期：** 2026.08.04

[v1.5.8](ver1-5-8.md) 讲的是记忆，这一版讲的是提供商——Gemini 原生 Embedding 2 端点、按模型设置的推理强度控制、Novita AI 网关——以及它们底下那些悄悄出错的路径：查询被当作文档来嵌入、`none` 反而打开了思考、能力崩溃以空白消息的形式出现。大多数安装可直接升级，但 **`docker-compose.ghcr.yml` 用户需在下一次 `up` 之前执行一次性的数据迁移**。

## 新增内容

### 通过原生 API 使用 Gemini Embedding 2

Gemini 嵌入配置现在默认使用 Google 原生的 `…/models/<model>:batchEmbedContents` 端点，模型为 `gemini-embedding-2`，以 `x-goog-api-key` 认证，端点随所选模型变化——包括通过网关前缀。现有的 `gemini-embedding-001` 配置有意保留在 OpenAI 兼容路径上：原生路由会发送 `taskType` 并对返回结果做 L2 归一化，迁移会改变其文档向量，并静默使基于这些向量构建的索引失效。将 `base_url` 指向原生 URL 即可让任意模型选用原生路径。

### 查询不再被当作文档嵌入

检索嵌入现在会携带其角色。LlamaIndex 将查询标记为 `search_query`、段落标记为 `search_document`，LightRAG 以同样方式映射自身的上下文提示，适配器需显式声明（`SUPPORTS_INPUT_TYPE`），因此从不发送角色的后端仍然不发送。目前只有 Cohere 发生变化——它要求该字段且原本就默认 `search_document`：文档向量不受影响，查询终于获得正确的角色。无需重建索引。

### 按模型设置的推理强度选择器

目录中的每个 LLM 模型在其上下文窗口旁新增可选的默认推理深度，仅在提供商实际支持时提供，并使用该提供商自己的术语（OpenAI 风格系列为 minimal/low/medium/high/xhigh，仅有自适应模式时为 adaptive，其余为简单的开/关）。**提供商默认（Auto）** 将选择权交给提供商。接入过程中发现两个 Anthropic 缺陷：`none` 反而以 4096 token 预算*打开*了思考；将存储的 `adaptive` 发送给较旧的系列会返回 400，而不是使用默认预算。

### Novita AI，以及运行在正确平台上的 MiniMax

Novita AI 加入 LLM 网关（`novita`、`https://api.novita.ai/openai`）。MiniMax 运行两个独立平台，其密钥**不可**互换，默认现在指向全球平台（`api.minimax.io`）而非中国大陆平台；记录了 `minimax-m3` 和 `minimax-m2.7` 的上下文窗口，检测也会读取 `context_size` 字段。

### Compose 部署保留整个 `data/`

`docker-compose.ghcr.yml` 只绑定了 `data/user`、`data/memory` 和 `data/knowledge_bases`，因此 `data/system`（JWT 签名密钥、账户、授权、各所有者的 Codex token）、`data/users`、`data/partners` 和 `data/cli-apps` 位于容器的可写层，每次重建都会丢失。现在挂载整个目录树，与其他 Compose 文件一致。命名卷和源码构建部署从未受影响。

### 本地容器内的 Codex 登录

默认的本地 Docker 和 Podman 部署将浏览器与服务器放在不同的回环网络上，OAuth 回调始终无法到达。现在提供临时的 `compose.codex-oauth.yaml` 覆盖文件（以及等效的 `docker`/`podman` 命令），仅在登录期间发布端口 `1455`/`1457`——并会拆除，端口归还给你的其他 Codex 客户端。参见 [CONTAINERIZATION.md](https://github.com/HKUDS/DeepTutor/blob/main/docs-for-dev/CONTAINERIZATION.md#temporary-local-codex-oauth-bridge)。

### 过去以空白形式出现的失败

抛出异常的能力——或请求不存在的能力——会在没有结论的情况下结束流，该轮次被持久化为 `completed` 且答案为空。现在错误被标记为终止，并通过 `DONE` 事件传递，因此该轮次以 `failed` 存储并附带消息，UI 显示出错原因而非空白气泡。

### 其他

- 保存的界面语言在首次加载时生效。它存放在后端的 `ui` 设置中，只有 Settings 路由会读取，因此其他页面在你在该浏览器中重新选择之前都以英文启动。本地选择仍然优先。
- 当分析模型编造出枚举之外的 `render_type` 或 `visual_genre` 时，Visualize 不再中止——枚举外的值被丢弃，字段回退到默认值。
- 类似凭据的查询参数（`key`、`api_key`、`token`、`access_token`）在向导、客户端和错误消息打印的每个端点中都会被脱敏。

## 升级说明

`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 变更，无需重建索引。

- **`docker-compose.ghcr.yml` 用户：在下一次 `up -d` 之前复制出你的状态。** 新的整树挂载意味着空的主机目录会遮蔽容器可写层中的内容，重新生成认证密钥（导致所有人登出）并以无任何非管理员账户的状态启动。那一条 `docker cp` 循环见 [CONTAINERIZATION.md → 一次性迁移](https://github.com/HKUDS/DeepTutor/blob/main/docs-for-dev/CONTAINERIZATION.md#one-time-migration-docker-composeghcryml-now-mounts-all-of-data)。
- **中国大陆平台上的 MiniMax：** 默认 base URL 现在是全球端点。将 `base_url` 设为 `https://api.minimaxi.com/v1`（或 `https://api.minimaxi.com/anthropic`）*并*使用中国平台密钥——密钥按平台发放。已保存的配置保留其现有 URL。
- **Gemini 嵌入：** 现有的 `gemini-embedding-001` 配置有意保持原样。新配置和 `gemini-embedding-2` 使用原生端点。
