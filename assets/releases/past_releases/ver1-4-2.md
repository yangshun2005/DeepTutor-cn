# DeepTutor v1.4.2 发布说明

**发布日期：** 2026.05.28

v1.4.2 是在 [v1.4.1](ver1-4-1.md) 基础上的稳定性与打磨版本。它打通了 Visualize 和聊天代理中的 Gemini 2.5+ 支持，修复了一个 ContextVar 回归问题（该问题会静默地将已认证请求路由到管理员工作区），加固了面向原生工具调用的推理模型的聊天协议，为所有聊天界面带来了平滑流式 UX，并新增了对 Lemonade 本地提供商的支持。

## 新特性

### Gemini 2.5+ 推理默认关闭

Gemini 2.5 / 3 默认开启思考功能，除非在请求中发送 `reasoning_effort: "none"`，否则会把整个 `max_tokens` 预算消耗在推理上。v1.4.2 将该逻辑集中到 `reasoning_params.default_reasoning_effort_for`，作为三条执行路径（OpenAI SDK、aiohttp 回退、推理 kwargs 构建器）共用的唯一事实来源。Visualize、Chat、Solve 以及代理循环在配置为 `gemini-2.5-pro` / `gemini-2.5-flash` / `gemini-3-*` 时，都不再返回空响应体。

### Visualize 流水线加固

修复了三种独立的故障模式：

- **按能力区分的 max_tokens 默认值** — Visualize 现在在 `agents.yaml` 中有自己的条目（16k tokens），从 `DEFAULT_AGENTS_SETTINGS` 播种，因此 `data/user/settings/agents.yaml` 已过时的现有用户会自动获得更高的上限，无需手动编辑。
- **SVG / HTML 根节点裁剪** — 当模型用散文包裹输出（"Here you go: `<svg>…`"）或在闭合标签同一行输出闭合围栏时，生成器代理现在会裁剪到最外层的 `<svg>…</svg>` / `<!doctype>…</html>`，确保渲染器始终收到干净的根节点。
- **审查步骤 JSON 模式崩溃 → 优雅回退** — 大型或复杂的 SVG 偶尔会在审查步骤中触发 JSON 模式转义问题。Visualize 现在会记录失败并交付未经审查的草稿，而不是让本轮崩溃，用户仍能看到渲染结果。

### 已认证请求落入正确工作区 (#485)

在 v1.4.1 中，`require_auth` 是一个同步 FastAPI 依赖。FastAPI 通过 `anyio.to_thread.run_sync` 调度同步依赖，后者在请求上下文的*副本*下的工作线程中运行它们——因此依赖内部的 `set_current_user(...)` 调用将用户安装在线程的上下文中，而该上下文在线程返回时被丢弃。端点随后读取未设置的默认值并回退到管理员工作区，静默地将每个已认证用户的读/写路由到本地管理员的数据。

`require_auth` 和 `require_admin` 现在是 `async def`，因此它们与端点在同一个 asyncio 任务中执行，`ContextVar` 在下游各处都可见。HTTP 和 WebSocket 入口点现在共享一个 `_install_current_user` 辅助函数，因此从令牌载荷解析出的用户对象在不同传输方式下完全一致。

### 推理模型 + 原生工具调用：标签协议修复

v1.4.1 试图对支持原生工具调用的推理模型耍小聪明——它告诉模型忽略 `TOOL`/`THINK`/`FINISH`/`PAUSE` 标签，仅依赖 `reasoning_content` 加 `tool_calls`，并在 `run_labeled_step` 内部将 `<think>` 前奏和任何传入的工具调用增量视为隐式标签解析。实践中这两个捷径都有害：当工具调用以 JSON 形式泄漏到内容流而非真正的 `tool_calls` 增量时，没有标签可供修复，循环会欣然将 JSON 当作答案视为 `FINISH`。多轮推理 + 工具工作流要么在修复重试上浪费迭代，要么静默提前终止。

在 v1.4.2 中：

- 推理 + 原生工具的系统提示告诉模型推理显示在单独的追踪区域，**但正式内容流仍必须以 `FINISH`/`TOOL`/`THINK`/`PAUSE` 中恰好一个开头。**
- `run_labeled_step` 不再将工具调用增量视为标签解析的权威依据，`implicit_think_label` 被忽略（保留以兼容 API）。缺失标签始终落到 `LABEL_UNKNOWN`，因此聊天流水线的协议修复路径会捕获它，而不是静默地错误路由本轮。
- 内联 `<think>...</think>` 前奏会实时流式传输到推理子追踪中，并从返回给循环的正式 `text` 中剥离——因此答案区域不再泄漏原始提供商标记。

### 所有聊天界面的平滑流式

上周为主聊天引入的 rAF 打字机（`useSmoothStreamText`）现在已接入 `AssistantResponse`，因此书籍聊天面板、测验追问标签页以及任何其他渲染助手消息的界面，在流式传输期间都获得相同的帧对齐节奏，对已完成消息则无操作直通。

配套修复：

- 书籍聊天面板和测验追问标签页将自动滚动移至 `useLayoutEffect`，并停止使用 `scrollIntoView({behavior: "smooth"})`——平滑动画在快速流式期间会与下一帧布局更新竞争，产生可见抖动。它们现在在布局阶段执行单次 `scrollTop = scrollHeight` 固定，与主聊天上 `useChatAutoScroll` 的行为一致。
- 书籍聊天面板用 `data-chat-scroll-root` 标记其滚动容器，使全局 `overflow-anchor: none` 规则生效（当代码块在光标上方重排时，浏览器内置的滚动锚定会与手动固定冲突）。
- `AssistantResponse` 现在已记忆化——当无关的流式兄弟组件更新父组件时，已完成的气泡不再重新解析 markdown。

### 侧边栏重新设计

展开侧边栏的聊天会话列表移入其独立的可折叠 **Recents** 区域，拥有独立的滚动视口，因此长历史不再将次要导航挤出屏幕。"New chat" 按钮已移除（点击导航中的 *Chat* 已可启动新会话），页脚中 GitHub 链接旁新增了指向 [deeptutor.info](https://deeptutor.info/) 的 Docs 链接。

每个会话现在渲染确定性的友好 Lucide 图标——sparkles、leaf、feather、cloud、droplet、sun、moon、flame、star 等——因此侧边栏乍看之下富有变化，且重新渲染时不会乱序。运行中的会话添加轻微的摆动动画；空闲会话保持静止。

### Lemonade 本地提供商

新增 `lemonade` 提供商绑定，面向 AMD Ryzen AI / NPU 运行时（默认基础 URL `http://localhost:13305/api/v1`）。通过端口 `13305` 自动检测，无需 API 密钥，在 README 的 Docker 主机网关部分以及提供商配置文档中与 Ollama / LM Studio / llama.cpp / vLLM 并列列出。

### 模型端点探测遵循 `DISABLE_SSL_VERIFY`

上下文窗口自动检测现在在设置了 `DISABLE_SSL_VERIFY` 时传递 `aiohttp.TCPConnector(ssl=False)`，与 HTTP 层其余部分的行为一致。自签名的本地推理服务器不再仅仅因为探测无法验证其证书而回退到默认上下文窗口。

## 测试

- `tests/api/test_auth_contextvar.py` — 锁定 #485 的回归：同步 `require_auth` 会丢失 ContextVar；异步版本在依赖边界上保留它。
- `tests/services/llm/test_reasoning_params.py` — 覆盖集中化的 `default_reasoning_effort_for` 映射。
- `tests/core/test_labeled_step_think_prelude.py` — 更新以反映新的"标签始终必需"语义。
- `tests/agents/chat/test_agentic_parallel_tools.py` — 验证推理 + 原生工具路径仍能解析多工具轮次。
- `tests/services/config/test_context_window_detection.py` — 模型端点探测遵循 `DISABLE_SSL_VERIFY` 并向 aiohttp 会话传递 `TCPConnector(ssl=False)`。

## 升级说明

- 从 v1.4.1 直接升级：`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。
- 如果你之前手动编辑过 `data/user/settings/agents.yaml` 以提高 Visualize 的 `max_tokens`，该值仍然优先。新的 16k 默认值仅播种给 `agents.yaml` 中完全未提及 Visualize 的用户。
- 如果你接入了 Gemini 2.5+ 模型并看到空或截断的输出，无需更改配置——默认关闭行为现在会自动生效。
