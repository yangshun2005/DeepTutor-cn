# DeepTutor v1.4.3 发布说明

**发布日期：** 2026.06.12

这是自 [v1.4.0](ver1-4-0.md) 以来最大的版本。TutorBot 成长为 **Partners**，Chat 收敛为单一 agent 循环，多用户实现真正的按用户隔离，Visualize、Co-writer、文件查看器、文档解析和 CLI 全面升级。[deeptutor.info](https://deeptutor.info/) 上的文档也同步重建——每个 Partner 渠道现在都有独立配置指南，提供中英文版本。

> **从 TutorBot 升级？** 迁移自动执行且不破坏数据：首次启动时你的 bot 会变为 Partners——渠道配置（含密钥）、模型选择和 soul 库都会保留，每个 bot 的人设变为其 `SOUL.md`。旧的 `data/tutorbot/` 目录保持原样，回滚安全。一处破坏性变更：HTTP API 从 `/api/v1/tutorbot/...` 移至 `/api/v1/partners/...`——请更新调用它的脚本。`[tutorbot]` pip extra 仍可作为 `[partners]` 的别名使用。

## 新增内容

### TutorBot → Partners

你的 bot 现在是 **Partners**——理念相同，执行更强：

- Partners 与产品 Chat 运行同一 agent 循环（独立的 nanobot 引擎已移除），因此 Chat 的每项改进都会自动惠及你的 IM bot。
- 生产级消息流水线：发送重试、去重、合并，以及按渠道的投递矩阵。
- Telegram、Discord 和飞书支持**实时流式回复**——答案边生成边渲染。
- 新增 **WeCom AI Bot** 渠道；共 15 个渠道连接器，覆盖 Slack、Discord 到钉钉、QQ 和 WhatsApp。
- Web 聊天现支持**附件**——可直接将图片或文件拖入 Partner 对话。
- 重写的 soul 模板库，带应用内编辑器。

### Chat 统一为单一循环

两阶段的 targeting/respond 流水线已移除。Chat 现在端到端运行单一探索型 agent 循环，原生工具调用——组件更少、工具使用更智能、不再有错误路由的轮次。新增 **Activity 头部**将状态行固定在顶部，答案返回后折叠思考/工具轨迹。

### 真正的多用户隔离

- 按用户授权 v2：工具、MCP 服务器和 exec 访问可在管理界面按用户控制。
- 工作区布局移至 `data/users/<uid>` + `data/system`；现有部署自动迁移。
- exec 运行器仅挂载调用用户的工作区子树（新增 `Dockerfile.runner`），沙箱代码永远看不到其他用户的文件。

### Visualize 重建

内联、主题感知的 SVG 渲染；结构化提示；本地校验 + 修复流程取代旧的整轮 LLM 审查——更快、更省、图表错误大幅减少。全屏现支持所有可视化类型。

### 日常工具更锋利

- **Co-writer** 通过 Mermaid 渲染流程图和时序图，选区范围的问题可从知识库和网络获取。
- **文件查看器**：浏览器内真正的 docx/xlsx 预览、拖拽调整大小，Activity 面板现与打开的文件并排显示。
- **MinerU 云端解析**作为本地后端的替代方案（`/settings/mineru`），题目提取现可捕获题型、难度和答案。
- **Office 技能开箱即用**——docx/pdf/pptx/xlsx 生成不再需要打开沙箱开关。
- **CLI 聊天重写**：对齐新循环协议，终端内交互式 `ask_user` 提示，Ctrl-C 取消，可折叠的思考输出。

### 重要修复

Qwen 模型不再将 JSON 包装泄漏到答案中，Windows 安装正确使用 UTF-8，Zulip bot 可靠捕获提及，文件描述符耗尽 bug 和误报健康检查已修复。

### 文档同步

[deeptutor.info](https://deeptutor.info/) 随本版本重建：每个 Partner 渠道的专属配置指南（英文 + 中文），全站截图更新，CLI 和服务器 API 参考已更新。

## 升级说明

- `pip install -U deeptutor`——迁移在首次启动时自动运行，且全部幂等。
- 旧 `multi-user/` 目录就地移至 `data/users/`；TutorBot bot 变为 Partners（见顶部说明）。
- 基于 exec 的技能现默认允许子进程。要恢复旧行为，在系统设置中将 `sandbox_allow_subprocess` 设为 `false`。
