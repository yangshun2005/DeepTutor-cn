# 🚀 DeepTutor v0.4.0 发布说明

**发布日期：** 2026.01.09

我们很高兴地宣布 DeepTutor v0.4.0 发布！本次发布带来**全新首页**、**扩展的 LLM 与 Embedding 提供商支持**、**RAG 模块解耦**、**Web 改进**，以及一系列小改进。

> 🚧 **可能存在的问题：** Docker 部署和本地 LLM/Embeddings 配置（Ollama、LM Studio）可能仍存在兼容性问题。我们正在积极改进。**欢迎提交 Issue 和 PR！** → [提交 Issue](https://github.com/HKUDS/DeepTutor/issues) | [贡献指南](https://github.com/HKUDS/DeepTutor/blob/main/CONTRIBUTING.md)

## ⚠️ 破坏性变更：环境配置

**环境变量名称已更新。** 请根据 `.env.example` 更新你的 `.env` 文件。

| 旧变量 | 新变量 | 说明 |
|:---|:---|:---|
| `OPENAI_API_KEY` | `LLM_API_KEY` | 现与提供商无关 |
| `OPENAI_API_BASE` | `LLM_HOST` | 重命名以更清晰 |
| `OPENAI_MODEL` | `LLM_MODEL` | 重命名以更清晰 |
| `EMBEDDING_DIM` | `EMBEDDING_DIMENSION` | 使用完整单词命名 |
| *(硬编码)* | `BACKEND_PORT` | 现可在 `.env` 中配置（默认：8001） |
| *(硬编码)* | `FRONTEND_PORT` | 现可在 `.env` 中配置（默认：3782） |

**新增必填变量：**
- `LLM_BINDING` — 提供商类型：`openai`、`ollama`、`azure_openai`、`anthropic` 等
- `EMBEDDING_BINDING` — 提供商类型：`openai`、`ollama`、`jina`、`cohere` 等

**新增可选变量：**
- `SEARCH_PROVIDER` — Web 搜索提供商：`perplexity`（默认）或 `baidu`
- `BAIDU_API_KEY` — 用于百度AI搜索
- `NEXT_PUBLIC_API_BASE` — 前端 API URL，用于**远程/局域网访问**（例如 `http://192.168.1.100:8001`）

> 💡 **远程访问：** 如果从网络中的其他设备访问 DeepTutor，请将 `NEXT_PUBLIC_API_BASE` 设置为服务器的 IP。未设置时默认为 `http://localhost:8001`（仅本机）。

> 📌 **需要操作：** 升级前请将 `.env.example` 复制为 `.env` 并更新配置。

## ✨ 亮点

### 🔌 多提供商 LLM 与 Embedding 支持

从仅支持本地扩展为完整的提供商生态：

| LLM 提供商 | Embedding 提供商 |
|:---|:---|
| OpenAI、Anthropic、Azure OpenAI | OpenAI、Azure OpenAI、Jina AI |
| Ollama、Ollama Cloud、LM Studio | Cohere、Ollama、LM Studio |
| Groq、OpenRouter、DeepSeek、Gemini | HuggingFace（OpenAI 兼容） |

`deeptutor/services/embedding/adapters/` 中新增基于适配器的架构，便于添加新提供商。

### 🧩 RAG 模块解耦

新增 `RAGService` 类，提供统一、与提供商无关的接口：

```python
from deeptutor.services.rag import RAGService

service = RAGService()  # Uses RAG_PROVIDER env var (default: raganything)
await service.initialize("my_kb", ["doc.pdf"])
result = await service.search("query", "my_kb")
```

> 📌 目前支持 **RAG-Anything**（MinerU + LightRAG）。更多后端即将推出！

### 🌙 深色模式与 UI 重构

- **主题切换**，支持系统偏好检测与 localStorage 持久化
- **可折叠侧边栏**，支持仅图标紧凑模式
- **设置页重建**：环境变量管理，按类别组织
- 所有页面统一深色模式样式

### ⚙️ 集中式配置

新增 `settings.py`，使用 `pydantic-settings` 实现统一配置：

| 类别 | 环境变量 |
|:---|:---|
| LLM | `LLM_BINDING`、`LLM_MODEL`、`LLM_HOST`、`LLM_API_KEY` |
| Embedding | `EMBEDDING_BINDING`、`EMBEDDING_MODEL`、`EMBEDDING_HOST`、`EMBEDDING_API_KEY`、`EMBEDDING_DIMENSION` |
| RAG | `RAG_PROVIDER` |
| TTS | `TTS_MODEL`、`TTS_URL`、`TTS_API_KEY`、`TTS_VOICE` |
| 搜索 | `PERPLEXITY_API_KEY` |

通过 `/api/settings/env` 运行时更新，自动持久化到 `.env`。

## 📦 变更内容

### 核心基础设施

- 新增 `settings.py`，使用 `pydantic-settings` 进行集中配置管理
- 新增 `deeptutor/core/llm_factory.py`，提供统一的 `llm_complete()` 函数
- 新增 `/api/embedding-providers` 路由，用于 Embedding 配置 CRUD
- 新增 `/api/settings/env` 端点，用于运行时环境管理

### 服务模块重构（`deeptutor/services/`）

```
services/
├── embedding/          # 🆕 基于适配器的 Embedding 提供商
│   ├── adapters/       # 提供商实现
│   │   ├── base.py, openai_compatible.py, jina.py, cohere.py, ollama.py
│   ├── client.py       # 统一 Embedding 客户端
│   ├── provider.py     # 提供商管理器（单例）
│   └── provider_config.py  # 多提供商配置持久化
├── llm/                # LLM 配置与客户端
├── rag/                # 🆕 解耦的 RAG 系统
│   ├── service.py      # 统一 RAGService 入口
│   ├── factory.py      # 流水线工厂
│   ├── pipelines/      # 后端实现
│   │   └── raganything.py, lightrag.py, llamaindex.py
│   └── components/     # 模块化 RAG 组件
│       ├── chunkers/   # 文本分块策略
│       ├── parsers/    # 文档解析器（PDF、Markdown、Text）
│       ├── embedders/  # Embedding 封装
│       ├── indexers/   # 向量与图索引器
│       └── retrievers/ # 稠密与混合检索
├── prompt/             # PromptManager 单例
├── tts/                # TTS 配置
└── setup/              # 初始化工具
```

- 🆕 重建**历史页**（`web/app/history/page.tsx`），改进活动视图
- 新增 `web/lib/theme.ts`，包含主题工具（`initializeTheme()`、`setTheme()`）
- 新增 `web/hooks/useTheme.ts`，React 主题 Hook

- 新增 `web/components/ChatSessionDetail.tsx`，用于历史页
- 重构 `Sidebar.tsx`，支持折叠模式
- 重建 `settings/page.tsx`，支持环境变量管理

### IdeaGen 改进

增强 4 阶段工作流：宽松筛选 → 探索想法 → 严格筛选 → 生成陈述

## 🐳 Docker

精简的单容器部署：

```bash
docker compose up -d
# Exposes: backend (8001), frontend (3782)
# Volumes: ./config (ro), ./data/user, ./data/knowledge_bases
```

通过 `NEXT_PUBLIC_API_BASE_EXTERNAL` 支持云部署。
