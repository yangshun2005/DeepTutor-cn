# DeepTutor v1.4.0 发布说明

**发布日期：** 2026.05.22

v1.4.0 是 v1.4 系列的 GA 版本。它包含 v1.4.0-beta 的全部范围（Auto Mode、三层 Memory 工作台、智能体化 Deep Research / Deep Solve / Question、LlamaIndex 聊天重构、统一能力基础设施 + i18n、Visualize/Animator 合并、新聊天工具、设置拆分、多用户隔离加固，以及 `deeptutor start` / `deeptutor init` 启动器），并在此基础上新增了一组聚焦于智能体引擎和运行时加固的修复。完整 beta 范围见 [v1.4.0-beta](ver1-4-0-beta.md)。

## v1.4.0-beta 以来的新增内容

### 推理强度 + 提供商思考标志
智能体引擎现在在一处统一归一化各提供商的"推理强度"，不再由每条流水线各自推导。

- `deeptutor/core/agentic/client.py` 中的 **`build_provider_extra_kwargs`** 会对照 `provider_registry` 解析 `reasoning_effort`，将 `minimal` / `minimum` 映射为正确的线上格式（DashScope 使用 `minimum`），并通过提供商的思考风格开关路由开/关意图——`thinking_type`（DeepSeek）、`enable_thinking`（Qwen 风格）或 `reasoning_split`。已知推理模型默认 `high`；`deepseek-v4-flash` 形态默认关闭思考。
- **`LLMClientConfig.reasoning_effort`** 已端到端打通。全部四条流水线——智能体聊天、question、research、solve——都将绑定 + 强度传入 `build_completion_kwargs`，因此单个用户级设置即可控制各能力的推理行为。

### 严格提供商的工具 Schema 回退
部分 OpenAI 兼容提供商会以非标准错误拒绝原生函数调用 Schema。`run_labeled_step` 现在会检测该情况，从请求中剥离 `tools` / `tool_choice`，重试一次，并发出警告进度事件，让用户知道本次调用以无工具的纯文本模式运行。对正常接受工具 Schema 的提供商，行为不变。

### 重启安全的轮次运行时
服务器或容器重启后，进行中轮次的数据库行会卡在 `running`，阻塞该会话的下一条消息，并让 UI 挂在一个永远不会完成的事件流上。

- **孤儿检测**——`TurnRuntimeManager` 现在会检查本进程是否仍持有该轮次的内存 runner。若否，则将持久化的轮次标记为 `failed`，并附带 `"Turn interrupted by server restart. Please retry your message."`
- **`start_turn`** 在创建新轮次前会清扫该会话的过期活跃轮次，用户重启后可立即重试。
- **`subscribe_turn`** 为孤儿轮次合成终止性的 `error` + `done` 事件，前端可干净地关闭流式状态，而非无限等待。

### 前端 API Base——Docker 占位符加固
`web/lib/api.ts` 对 `NEXT_PUBLIC_API_BASE` 占位符的检测从精确匹配改为子串 token 检测，并暴露 `isApiBasePlaceholder()` 供复用。这能容忍此前会漏过并导致设置页空白且无可见错误的 Docker 占位符形态小改动。beta 中随附的未使用自动生成文件 `web/.env.local` 已移除。

### LLM 配置探测——更清晰的状态文案
`/settings/llm` 探测现在会在冒烟补全后输出明确的一行："Basic LLM completion succeeded. Chat additionally validates streaming and provider tool compatibility at runtime."，让用户知道该探测有意不覆盖聊天所走的流式 / 工具调用路径。

### CLI 聊天 REPL——配置面与文档对齐
`deeptutor chat` REPL 面已收紧，与 [deeptutor.info](https://deeptutor.info) 上的公开文档一致。

- `deeptutor chat --config key=value` 和 `--config-json '<json>'` 无需先进入 REPL 即可注入初始配置。
- `/config set key value` 和 `/config set key=value` 均被接受；JSON 值（`[…]`、`{…}`）通过 `shlex` 正确解析。
- 反斜杠续行可在一轮中发送多行提示。
- `/refs` 打印结构化状态快照（会话、能力、工具、KB、历史、笔记本、语言、配置），而非单行暗色文本。
- `deeptutor plugin info <name>` 现在还会返回 `cli_aliases` 和能力 `availability` 块。

### 仓库与文档卫生
- 公开文档站点的新 Issue 模板（`.github/ISSUE_TEMPLATE/docs.yml`）。
- `AGENTS.md` 已更新，反映 Auto Mode、工具门控和当前能力阶段。
- `.gitignore` 覆盖 `.playwright-cli/`；移除了过期的 `.playwright-cli/` 截图、`.env.example_CN` 和 `DeepTutor.code-workspace`。

## 升级说明
- **从 v1.4.0-beta 升级：** 直接替换。PyPI 安装用 `pip install -U deeptutor`（PyPI 将 `1.4.0` 归一化到 `1.4.0b0` 之上）。Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。
- **推理强度** 现在从 `LLMConfig.reasoning_effort` 读取。若你此前在 `extra_body` 中手动设置提供商思考标志，智能体仍会尊重它们，但推荐路径是设置 `reasoning_effort` 并让引擎映射。
- **重启恢复** 自动进行。升级后，此前崩溃遗留的卡在 `running` 的数据库行将在其会话下次打开时被终结。
- **Beta 产物清理：** `web/.env.local` 由旧启动器自动生成，已不再需要。若你曾用该文件手动重建前端，请在下次构建前删除它。
