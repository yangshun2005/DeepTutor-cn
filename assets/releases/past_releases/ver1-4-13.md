# DeepTutor v1.4.13 发布说明

**发布日期：** 2026.06.27

这是 [v1.4.12](ver1-4-12.md) 的修复与打磨后续版本：非拉丁文字名称的伙伴可正常创建，并可分配给指定用户；多用户模式下登录后 Logo 正常渲染；小型知识库检索稳定可靠。可直接升级，无需迁移。

## 新增内容

### 伙伴：支持任意语言名称，支持管理员分配

现在可以创建使用中文（或任意非拉丁文字）名称的伙伴——id 会保留 Unicode 字母，不再退化为空 slug。伙伴同时成为可授权资源：管理员可将指定伙伴分配给指定的非管理员用户，这些用户随后可在聊天中查看、连接并咨询该伙伴。伙伴仍运行在各自隔离的工作区中，伙伴 CRUD API 仍仅限管理员——授权只开放对已分配伙伴的*使用*权限。

### 多用户：登录后 Logo 与静态资源正常渲染

在多用户部署中，登录后侧边栏 Logo 和登录横幅显示异常（issue #599）：认证网关将 Next.js 图片优化器无 Cookie 的环回请求重定向到了 `/login`。现在公共静态资源绕过网关，Logo、favicon、字体和图标均可正常加载。中间件的路由策略已迁移至独立的纯函数模块，并配有单元测试。

### 小型知识库检索稳定可靠

混合（BM25）检索在仅含一两个文档的知识库上会崩溃，因为请求的结果数超过了已索引的分块数。现在结果数会被限制在语料规模以内，小型知识库会返回现有内容，而不会在查询时报错。

### 所有格式统一上传上限

文档上传现在所有格式共用单一的 **200 MB** 上限；此前单独设置的、会拒绝较大 PDF 的较低上限已移除。容器内代理的请求体上限已同步提高，大文件上传不会再被静默截断。

### 可移植的容器启动

容器的 `supervisord` 配置现在可在 rootful Docker/Podman 以及使用 `userns_mode: keep-id` 的 rootless Podman 下正常启动。它不再固定自身权限，也不再写入 root 拥有的路径，消除了 rootless keep-id 下的启动失败（以及一个仅影响观感的 pidfile 警告）。

## 升级说明

从 v1.4.12 可直接升级：`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无需迁移，现有单用户配置行为不变。在多用户部署中，将伙伴分配给用户是授权编辑器中的新选项——不使用则无任何变化。
