# DeepTutor v1.6.5 发布说明

**发布日期：** 2026.09.06

v1.6.5 为 DeepTutor 提供了一个专属工作文件夹。你指定一个目录，助手就能浏览、读取并搜索其中已有内容，而它生成的所有文件都落在同一个可预期位置——任何文件离开该位置都需要你批准。围绕这一点，代码执行合并为单一工具，Mastery Path 学会何时可以教学、何时可以重新设计，Settings 也终于能区分“未配置”与“已损坏”。本地安装可直接升级；Docker 用户请阅读下方的工作区挂载说明。

## 新增内容

### 由你选择的内容工作区

将 DeepTutor 指向任意文件夹，它就成为整个会话的工作目录。助手可以列出、读取并搜索其中内容，因此无需上传即可使用你自己的材料。生成的文件落在 `outputs/`，将文件从 `outputs/` 移到文件夹其他位置是需用户明确批准的步骤，不会悄悄发生。可在 Settings 中管理，或使用 `deeptutor workspace show`、`set` 和 `reset`。

### 单一工具执行代码

`code_execution` 和 `exec` 原本是两个工具干同一件事。现在合并为单一的 `exec`，支持 Python、C、C++ 或 shell。一轮中的每次调用共享同一工作目录和同一依赖环境，因此后续调用可以重新打开并修改先前调用写入的文件，而无需从头开始。

### Mastery Path 知道自己处于哪种模式

学习目标现在在三种模式间切换——设计大纲、推进大纲和复习——可用工具也随之变化。只有 `outline` 能修改地图，因此导师无法在课程中途悄悄改写你的计划；只有 `study` 和 `review` 能考查你，且在大纲真正确定前都不会开始。提出的问题以卡片形式出现并结束本轮，因此回答是一个有意的动作。

### Settings 区分“未设置”与“已损坏”

概览将每项能力评为阻塞项、警告或建议，并记录该安装是否真正依赖它。你从未配置的可选视频模型不再被报告为故障；而你*确实*选择且无法工作的解析器则会被报告。该矩阵只包含标识、布尔值和原因码——提供商 URL、模型名称、凭据和异常文本保留在服务器上，且构建矩阵时从不调用模型提供商。

### 问题在编写过程中即出现

`ask_user` 卡片过去会在介绍性文字出现几秒后一次性到达。现在卡片随其介绍一起出现，并随着模型编写选项就地增长，因此本轮在向你提问时不再陷入沉默。

### 可保留的视频学习

已连接的 Invidious 账户拥有自己的适配器，转录提示在播放推进时保持可见，带时间戳的笔记可导出为 Markdown。视觉学习板收集会话产生的内容。

### 知识库固定其索引模型

LightRAG 知识库记录索引它们所用的模型，并允许你为每个知识库固定这些模型，因此重新索引不会悄悄改变现有索引背后的嵌入。

### 通过网络使用子代理

加固的远程 Hermes 后端加入本地子代理框架，因此被咨询的代理可以在本机之外运行。

## 修复

中文 Markdown 在流式传输时保留原始内容；不安全的网页搜索标题和摘要被过滤；Responses 轮次中 DeepSeek 推理重放的 `400` 会回退而非使本轮失败；Settings 在其自身窗格内滚动；旧版 Mastery `/study` URL 重定向到 `/sessions`；测验卡片文本解码 unicode 转义；恢复的阅读材料延迟加载；更新时正确检测源码检出。

## 升级说明

运行 `pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。Settings、书籍、会话和学习数据无需手动迁移。

- **`code_execution` 工具已移除**——其工作已并入 `exec`。提及 `code_execution` 的自定义提示、技能或插件应改为调用带 `language` 的 `exec`。
- **Docker 工作区挂载。** 容器现在期望内容工作区位于稳定路径 `/workspace`。在运行 `python scripts/docker_compose.py up -d` 前设置 `DEEPTUTOR_WORKSPACE_HOST=/absolute/host/folder` 以选择宿主机文件夹；省略则保留 `./data/user/workspace`。辅助脚本会为你创建该文件夹及其 `outputs/`，因此绑定挂载不会归 root 所有。
- **沙箱运行器可见范围更小。** 它不再挂载 `data/users`；它以只读方式接收 `/workspace`，`/workspace/outputs` 可写，受 `DEEPTUTOR_RUNNER_ALLOWED_WORKDIRS` 限制。执行的代码不再能访问其他账户的设置、聊天历史或知识库。
- **多用户部署共享挂载的工作区。** 设置 `DEEPTUTOR_WORKSPACE_ROOT` 时——所有提供的 Compose 文件都会设置它——该文件夹就是每个账户的内容工作区，且该路径在 Settings 中显示为锁定。不设置则保留每用户工作区。
- 导入 `deeptutor.config.schema`、`.defaults`、`.accessors` 或 `.constants` 的扩展必须迁移到公开设置接口；这些模块已被移除。
- 英文和中文指南已在 [deeptutor.info](https://deeptutor.info/) 同步更新。
