# DeepTutor v1.5.7 发布说明

**发布日期：** 2026.07.31

这是 [v1.5.6](ver1-5-6.md) 的后续版本，为导师引入了 DeepTutor 此前从未提供的工具：一个精选的托管 MCP 服务商店，每人自行安装；以及来自 CLI-Anything 目录的 101 个命令行应用，聊天代理可直接调用。两者都配备了共享部署真正需要的授权与隔离——安装是特权操作，运行不是，且任何用于授权个人的信息都不会留在代码沙箱可读取的位置。即插即用——无需迁移。

## 新增内容

### 自行安装的 MCP 商店

**学习空间 → MCP 服务** 是一个商店，包含 45 个精选托管服务器，一键即可为自己添加，也可通过 URL 配置任意远程服务器。每个目录端点都通过发送真实的 MCP `initialize` 验证过，且不联系任何 logo CDN——否则每次渲染商店都会把你的已安装服务列表发送给第三方。返回 `401` 的服务器（Notion、Linear、Sentry、Asana、monday、Canva、Prisma）通过 OAuth 2.1（PKCE 与动态客户端注册）登录；后台重连不会阻塞在授权页面上，只报告 `needs_auth`，由 UI 提供连接按钮。静态密钥按引用存储，连接时在内存中解析，因此令牌绝不会落入会被显示、由 API 返回或复制到日志的配置文件。`stdio` 条目拒绝自助安装：命令即以应用用户身份执行宿主机。

MCP 不再在设置中配置——`/settings/mcp` 重定向到商店——工具选择器现在将数百个工具折叠为每个服务一行。

### 导师可运行的 CLI 应用

**学习空间 → CLI 应用** 收录了从两个 [CLI-Anything](https://github.com/HKUDS/CLI-Anything) 注册表快照的 101 个工具，聊天代理可直接调用已安装的应用，且仅在该应用需要时才加载其使用指南。安装仅限管理员，因为 `pip install` 会在应用容器中运行包自带的 `setup.py`——无论如何谨慎都无法将其变为自助操作。注册表的 `install_cmd` 从不执行：它被解析为计划，由 DeepTutor 构建 argv（注册表中已包含 `curl … | bash`），npm 安装脚本被强制禁用，构建失败的更新会回滚到可用环境。66 个第一方 harness 条目固定到一个经过审查的 CLI-Anything 提交；指向不同上游的一律标记为第三方，以便安装时做出知情选择。

应用落在 `data/cli-apps`，每个应用一个环境，以**只读**方式挂载到沙箱运行器。这种分离正是关键：逃逸的命令无法覆盖应用的入口点，从而让之后每个账户的每一轮都运行被替换的版本。

### 沙箱无法触及的凭据

所有用于授权*个人*的内容都移至 `data/system`——数据树中唯一从不绑定挂载到运行器的分支。Codex OAuth 令牌现在位于 `data/system/user-secrets/<owner>/private/openai-codex/`，每用户 MCP 配置位于 `data/system/user-mcp/<owner>.json`，MCP 令牌和 API 密钥也在其旁。现有 Codex 登录在首次使用时自行迁移，且迁移拒绝通过符号链接目录执行，以免误迁移其他账户的存储。

这堵住的是真实暴露而非理论风险：运行器收到的每用户挂载是整个用户根目录，因此保存在 `data/users/<uid>/` 下的凭据可被其他任何账户的沙箱 shell 读取——以及写入。

### 按人管控的插件工具

授权新增 `cli_apps` 白名单，与 MCP 工具已有的默认拒绝姿态一致：已安装的应用是运行在沙箱中的第三方代码，部署安装一个应用与允许每个账户运行它并非同一决策。在此之下，每轮注册表视图将某用户的提供方工具完全排除在进程全局注册表之外——两个租户的服务器共享工具名时不再互相覆盖——并在 `execute` 阶段拒绝未授权工具，而不仅在清单中，因为文本协议回退可能合成从未提供的名称。

### 告诉你窗口有多满的输入框

输入框中的标签报告本轮实际放入模型上下文窗口的内容及其占用，基于已组装好的提示块、工具 Schema 和消息列表测量而非重新推导——因此读数不会与实际发送的内容偏离。长对话还会在转录区左侧边栏显示刻度轨，每个你提过的问题一个刻度，用于回溯历史。

### 手机上的 DeepTutor

工作区和工具布局现在在小屏幕上折叠为单列外壳，侧边栏滑出，而不再渲染超出视口边缘的桌面三栏布局。

### 其他修复

- 发送后输入框保持焦点，切换标签页再返回时恢复焦点（[#720](https://github.com/HKUDS/DeepTutor/pull/720)）。
- 发布的容器镜像带有来源和 SBOM 证明（[#722](https://github.com/HKUDS/DeepTutor/pull/722)）。
- 应用镜像中安装了 `git`，运行器镜像中安装了 Node 运行时，二者分别是应用安装器和 npm 打包应用控制台脚本所必需的。

## 升级说明

从 v1.5.6 即插即用：`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 或配置变更，现有 Codex 登录会延续——其凭据在首次解析时自行迁移。

- **docker-compose 部署应重新 up**，而非仅重启：运行器服务新增只读的 `./data/cli-apps` 挂载，缺少它时已安装的 CLI 应用虽被收录但无法执行。
- **在设置中配置的 MCP 服务器保持原样**——部署级 `mcp.json` 未变，仍归管理员所有。新商店是并行的、按账户的；`/settings/mcp` 现在重定向到它。
- **安装 CLI 应用仅限管理员，分配是第二步。** 非管理员账户在授权指定之前看不到已安装的应用，与 MCP 工具和技能的工作方式相同。
