# DeepTutor v1.5.16 发布说明

**发布日期：** 2026.08.22

[v1.5.15](ver1-5-15.md) 在书籍阅读器下新增了采集收件箱，却因此导致页面无法翻页。本次已修复该问题，同时新增一个已连接的知识源——由自有插件填充的 **MarginNote 4** 库——并修复了一系列仅在特定网关下才会出现的故障：工具调用 id 不断增长直至被提供商拒绝、因我们有意省略的参数导致嵌入请求被拒、以及仅在命名了正确绑定时才生效的温度限制。可直接升级——无需迁移，无需重建索引。

## 新增内容

### MarginNote 4 作为知识库

连接一个库后，MN4 插件会将你的笔记、摘录、卡片和思维导图节点推送到其中——无需上传、无需索引，也不会从 MarginNote 中复制任何内容。在库的 **Devices** 标签页中配对设备，将一次性令牌粘贴到插件中，同步内容便会增量到达 DeepTutor 自有的存储中。

在该库上发起一轮对话时，会使用其自有的七个工具而非 `rag`：跨摘录和笔记文本搜索、读取单个对象、按类型列出、遍历文档的子节点、跟随链接、按标签过滤，以及读取思维导图卡片。聊天循环会像处理 Obsidian 仓库那样将对话交给这些工具，因为不含索引的库没有可供检索分块的内容。

由 [@evan188199-tech](https://github.com/evan188199-tech) 贡献，[#931](https://github.com/HKUDS/DeepTutor/pull/931)。这是第一阶段——只读导航；写回功能已在规划中。

### 书籍页面恢复翻页

采集收件箱作为阅读器 flex 行的第二个子元素加入，却没有将该行设为 flex 列，导致 `PageReader` 的 `h-full` 塌缩为 `auto`：正文停止滚动，翻页页脚被完全裁出视野。一行布局修复；回归期间我们运行的所有检查均为绿色，因为此处对类型检查和测试均不可见。

### 流式工具调用 id 不再增长

OpenAI 兼容提供商前面的路由器可能会在每个增量块中重发完整的工具调用 `id`。三个核心位置将其追加而非赋值，导致 id 每块增长一份——[#937](https://github.com/HKUDS/DeepTutor/issues/937) 中出现了 47,241 个字符——超过提供商 64 字符上限后，每一轮都以 `Invalid 'messages[i].tool_calls[0].id': string too long` 失败，表现为“无法从模型输出中生成有用的响应”。`name` 在两个位置存在完全相同的缺陷，在该网关上处于潜伏状态，在任何重复名称的网关上则致命。三个位置现在共用一个累加器：`id` 和 `name` 完整到达并直接赋值，`arguments` 以片段到达并拼接。

### 模型限制跟随模型，而非路由

Kimi 模型在服务端锁定温度，并拒绝显式值（HTTP 400）。该覆盖自 v1.5.5 之前就已存在，但它是从*已配置绑定的*规格中解析的——因此对 [#938](https://github.com/HKUDS/DeepTutor/issues/938) 从未生效，该用户做了最普通的事：将 `binding="openai"` 指向 Moonshot。路由并非执行限制的一方，因此路由不再做决定：已配置的规格若对模型有所说明则优先，否则由模型自身的厂商规格作答。所有模型内在的覆盖在通用绑定背后都以同样方式丢失了。

### 嵌入从要求 `encoding_format` 的网关中恢复

ModelScope 将缺失的 `encoding_format` 读作 `''` 并拒绝请求（[#934](https://github.com/HKUDS/DeepTutor/issues/934)）；SiliconFlow 在该字段*存在*时拒绝，这正是我们省略它的原因。相同的 Qwen3-Embedding 权重服务于这一分歧的两侧，因此没有任何默认值或模型族规则能同时满足两者。正常路径字节完全一致——字段仍然省略——而同时指明该参数和我们即将发送的值的 400 响应，会获得恰好一次使用 `encoding_format="float"` 的重试。

### 索引中的图像并行描述

LlamaIndex 流水线此前逐个描述提取的图像。现在它们并发运行，带有每图像超时和进度行，可通过 `image_description_concurrency`（默认 4）和 `image_description_timeout_seconds`（默认 60）调整。被证实不接受图像的模型不再在不带图像的情况下重试——在那里图像*就是*问题本身，而根据周围文本编造的描述会被当作事实索引。由 [#933](https://github.com/HKUDS/DeepTutor/pull/933) 贡献。

### LightRAG 收敛而非挂起

针对 LightRAG 基础的传输故障现在会在重试前分类：可重试的 HTTP 状态最多获得三次有界尝试，`Retry-After` 设有上限，其他情况立即失败，且两个重试层不再相乘。取消操作会清理而非泄漏，Codex 传输故障会传播而非被吞掉。由 [#940](https://github.com/HKUDS/DeepTutor/pull/940) 贡献。

### 其他

- **索引进度行可翻译。** 全部 22 个生产者此前向日志框发送硬编码英文。现在传输内容携带模板及其值，前端以你的语言渲染；无 i18n 的消费者——日志、快照、CLI——读取的内容与之前完全一致。
- **已删除的知识库不再困扰你的会话。** 其名称曾残留在每个会话的上下文标签中（[#936](https://github.com/HKUDS/DeepTutor/issues/936)）。
- **开发用 Docker 镜像重新拥有前端。** 其 supervisor 针对生产独立包运行 `node scripts/dev.mjs`，而该包不含源码、配置和 `scripts/`，因此 `docker compose -f docker-compose.dev.yml up` 启动即死（[#906](https://github.com/HKUDS/DeepTutor/issues/906)）。该阶段现在采用构建器的整个 `web/` 目录树。生产镜像从未受影响。
- **提供商的拒绝响应体在进入日志前设有上限。** 该日志的存在是为了让你能将 `deeptutor.jsonl` 附加到缺陷报告，而某些提供商会将拒绝的请求——Schema，有时是消息——回显到其中（[#930](https://github.com/HKUDS/DeepTutor/pull/930)）。
- **两个 MarginNote 库不再能占用同一存储。** “My Lib”和“My/Lib”都派生 `My_Lib.db`；注册现在按名称拒绝冲突，删除库会移除我们为其创建的存储。
- **MN4 设备桥接先检查凭据。** `/sync` 和 `/heartbeat` 在验证令牌之前就解析存储，因此未认证的 POST 会为每个不同的 header 值创建一个数据库——且配对写入调用者的工作区，而设备路径读取默认工作区，这可能使每次同步永远 403。

## 升级说明

`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 变更，无需重建索引，无需迁移。

- **MarginNote 4 库初始为空。** 连接它，在 **Devices** 标签页配对设备，然后将一次性令牌粘贴到 MN4 插件中——令牌仅显示一次，且只保留其哈希。存储位于 `data/user/marginnote4/<name>.db`，随库一同删除；MarginNote 本身不受任何影响。
- **MarginNote 库不会被 `rag` 扫描。** 与 Obsidian 仓库一样，它们仅通过自有工具访问，因此 Book 和 `rag_search` 会跳过它们，而非报告空结果。
- **新的图像描述参数适用于下一次索引构建**，而非下一个问题，位于 **Settings → Knowledge Base** 下。
