# DeepTutor v1.3.3 发布说明

**发布日期：** 2026.04.30

v1.3.3 是 v1.3.2 之后的快速跟进版本。它扩展了提供商覆盖范围，新增 NVIDIA NIM 和 Gemini 嵌入，将 Space 统一为把聊天历史、笔记本、题库条目、技能和记忆附加到单轮对话的入口，并继续围绕 RAG 重建索引、思考模型清理、TutorBot 历史和持久化会话上下文进行稳定性改进。

## 亮点

### 提供商与嵌入覆盖

DeepTutor 现在开箱即支持更多托管提供商配置，并保持运行时配置路径与 Setup Tour 和 `.env` 示例一致。

- **NVIDIA NIM 成为一等 LLM 提供商** - 提供商自动检测现在能识别 `nvapi-` 密钥和 NVIDIA API 基址，默认使用 `https://integrate.api.nvidia.com/v1`，并避免发送 `stream_options.include_usage`，因为 NIM 在该选项存在时可能挂起。
- **Gemini 嵌入端到端可用** - 嵌入运行时元数据、端点校验、Setup Tour 选项、模型建议和 `.env` 示例现在都包含 Gemini，支持 `gemini-embedding-001`、3072 维度和 `GEMINI_API_KEY` 回退。
- **提供商专属嵌入密钥在 Settings 写入后保留** - `.env` 写入现在会保留 SiliconFlow、DashScope、Cohere、Jina 和 Gemini 等密钥，而不只是保留旧的核心提供商集合。
- **依赖解析更稳健** - 放宽了 NumPy 上限以支持 `deeptutor[all]` 中当前的 Manim 安装，Windows 安装文档现在明确列出 Visual Studio Build Tools / C++ 工作负载前置条件。

### Space、聊天上下文、技能与记忆

聊天输入区现在将所有学习上下文视为 Space 上下文，不再把引用、技能和记忆分散到不同控件中。

- **Space 打开后进入聊天历史** - Space 入口现在落在新的聊天历史页面，可直接在 Space 工作区中搜索、刷新、重命名、删除和重新打开之前的对话。
- **单一 Space 菜单驱动工具栏和 `@` 提及** - 旧的內联 `AtMentionPopup` 被共享的 Space 菜单取代，用于聊天历史、笔记本、题库条目、技能和记忆，无论从工具栏打开还是输入 `@` 打开。
- **技能选择更清晰** - 技能现在在带搜索、标签、显式多选和自动模式的完整选择器中打开，而不是输入区旁的小型内联下拉菜单。
- **记忆可按轮附加** - 用户可通过新的记忆选择器选择运行摘要、档案或两者。请求会发送 `memory_references`，后端只注入选中的记忆文件。
- **上下文标签展示完整轮次设置** - 选中的历史、笔记本、题库条目、技能和记忆在发送前都显示为可移除标签；已发送的用户消息也会显示匹配的请求快照徽章。
- **Answer Now 和会话水合保留上下文** - 重放的轮次和加载的会话现在会从持久化消息元数据中水合笔记本、历史引用、题库引用、技能、记忆引用和附件。

### 会话持久化与消息规范化

对话状态现在记录更多用户实际发送时的上下文，并更防御性地处理非文本消息内容。

- **消息元数据被持久化** - SQLite 会话存储新增 `metadata_json` 列，并为用户消息存储 `request_snapshot`，包括能力、工具、选中的知识库、语言、配置、附件、Space 引用、技能和记忆选择。
- **WebSocket 轮次显式接受记忆和技能** - 传入载荷将 `memory_references` 规范化为 `summary` / `profile`，将技能规范化为字符串列表，并将两者物化到消息元数据中。
- **TutorBot 历史处理多模态内容** - 机器人历史和最近的机器人预览将字符串、数组、对象和图片式内容规范化为安全的显示文本，同时从 API 响应中剥离内部 `reasoning_content`。
- **前端消息预览更安全** - 共享消息内容工具现在接受未知内容，将自定义对象字符串化，将图片部分渲染为 `[image]`，并在聊天和会话列表中一致地截断预览。

### 记忆、笔记本与思考模型清理

v1.3.2 引入的思考输出清理现在覆盖更多持久化存储面，并在格式错误的记忆重写损坏档案或摘要文件之前将其拒绝。

- **记忆重写必须匹配预期结构** - 档案和摘要刷新现在在写入前验证允许的章节标题。如果思考模型回答用户而不是返回结构化记忆，写入会被拒绝而非持久化。
- **记忆上下文显式化** - `build_memory_context()` 现在仅在请求这些文件时包含 `summary` 和/或 `profile`，与新的按轮记忆选择器一致，避免意外的默认记忆注入。
- **笔记本摘要被清理和修复** - 笔记本写入、流式摘要保存和笔记本加载都会从摘要中剥离思考标签；较旧的笔记本记录在读取时尽可能修复。
- **流式摘要块更干净** - 生成的笔记本摘要会先组装、清理，再在清理后发出，因此空块或仅草稿的块不会流式发送给客户端。

### RAG 与知识库韧性

RAG 校验现在能在检索前捕获更多无效的持久化索引，并在用户需要重建索引时返回更清晰的事件。

- **索引就绪时陈旧的 processing 知识库恢复** - 如果 `kb_config.json` 卡在 `processing` 或 `initializing`，但磁盘上已有就绪的 LlamaIndex 版本，知识库信息会报告 `ready` 并隐藏陈旧的进度条，而不是让 UI 停留在永久处理状态。
- **更多向量存储被校验** - LlamaIndex 存储现在检查默认向量存储、`storage_context.vector_stores` 以及持久化的 `*vector_store.json` 嵌入字典中的 null、丢失、非数值、非有限或不一致向量。
- **无效索引失败发出面向用户的状态事件** - RAG 搜索现在通过工具事件流发送带 `needs_reindex` 的结构化错误状态，并避免将已知的无效索引失败视为成功的检索尝试。
- **底层向量错误更少暴露** - 已知的无效嵌入/索引失败会被记录并呈现为重建索引指引，而不是在面向用户的日志中出现原始的 `NoneType * float` 式回溯。

## 测试

- 新增知识管理器覆盖：当有效索引版本已存在时，将陈旧的 `processing` / `initializing` 状态提升为 `ready`。
- 新增提供商覆盖：NVIDIA NIM 注册表元数据、流选项行为、Gemini 嵌入运行时默认值、端点校验、Setup Tour 提供商选项和 `.env` 密钥保留。
- 新增会话和 WebSocket 覆盖：`metadata_json`、请求快照、技能规范化、记忆引用解析和轮次物化。
- 新增记忆和笔记本覆盖：思考标签剥离、无效记忆重写拒绝、选择性记忆上下文注入和读取时摘要修复。
- 新增 RAG/LlamaIndex 覆盖：多向量存储校验、磁盘持久化的无效向量、`needs_reindex` 状态事件和净化后的原始日志。
- 新增 TutorBot 和前端消息内容覆盖：非字符串、多模态、对象、图片和截断的消息内容。

## 升级说明

- 现有 SQLite 会话数据库在会话存储首次打开时会就地迁移，新增 `messages.metadata_json` 列。
- 依赖隐式记忆注入的自定义 WebSocket 客户端现在应传入 `memory_references: ["summary"]`、`["profile"]` 或两者。空或缺失的记忆引用有意表示"不附加长期记忆"。
- 仍报告无效持久化向量的知识库应在确认活动嵌入提供商、模型、维度和端点 URL 后重建索引。
- 笔记本摘要流式客户端应预期在组装后收到清理过的摘要输出，而不是依赖每个原始模型块都被转发。
- NVIDIA NIM 用户应在新提供商下配置 OpenAI 兼容模型，并为该网关保持 `stream_options.include_usage` 禁用。
