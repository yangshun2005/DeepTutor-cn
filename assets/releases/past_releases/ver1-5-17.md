# DeepTutor v1.5.17 发布说明

**发布日期：** 2026.08.25

[v1.5.16](ver1-5-16.md) 接入了 MarginNote 库，并解决了一批网关故障。本次发布改变了 **Partner** 的归属：Partner 不再是仅管理员可操作的部署级资源，而是每位成员自行创建、拥有并与之进行私密对话的资源——管理员仍可通过授权把自己的 Partner 借给他人使用。围绕这一变化，本次还带来了可跟踪 **GitHub 仓库**的知识库、My Agents 下的 **Antigravity CLI**、在浏览器中绘制而非写入日志文件的微信二维码，以及保留你所声明可选组件的容器。现有 Partner 继续可用并会自动迁移；唯一的行为变化仅影响非管理员用户——他们现在能看到过去对其关闭的 **Partners** 页面。

## 新增内容

### Partner 归属于人，而非部署

过去所有 `/api/v1/partners` 路由都统一置于管理员门禁之后，成员只能与管理员分配给自己的 Partner 对话，别无其他。现在三种权限层层嵌套：**管理**（创建者及任意管理员）涵盖 soul、渠道、模型、资产、生命周期与删除；**使用**额外包含管理员指派的人员，意味着可以发起对话；其他人则无法得知该 Partner 是否存在——无主 Partner 与不可见 Partner 的响应完全一致，因此无法通过 id 枚举探测。

对话跟随人，而非 Partner。两人与同一伴侣对话时永远看不到彼此的会话线程，各自在 Web 应用中以自己的账号读回。授权机制仍然存在且形态未变，但现在只提供*管理员管理*的 Partner：成员自行创建的 Partner 是否共享由本人决定，因为其 `SOUL.md` 通常是个人撰写的。

### 聊天账号可携带你的 DeepTutor 身份

通过 QQ 或 Telegram 访问的 Partner 过去只能识别渠道内的发送者 id，因此每条入站消息都是匿名的——消息落入共享线程池，Partner 从管理员工作区而非发送者自己的库中作答。在 Web 应用中向 Partner 索取一个验证码，从你想关联的聊天账号发送 `/link <code>`，此后该发送者就是你：对话对你的账号私密，可在浏览器中读回，Partner 会像在 Web 轮次中一样读取你的知识、笔记本和记忆。

### 两个 Partner 可共享同一渠道

渠道运行时状态——bot token、长轮询游标、会话引用、E2EE 设备存储——过去按*渠道*而非按 Partner 存放在同一目录，导致同一渠道上配置的两个 Partner 会读取彼此的凭据并覆盖彼此的游标。两者中只能有一个在线。现在状态存放在 `data/partners/<id>/channels/<channel>/` 下，首次启动时在归属明确的情况下将旧目录树**复制**过去——已保存的 token 与某个 Partner 配置的 token 匹配，或只有一个 Partner 启用了该渠道。真正无法区分归属时，会重新认证一次，而不是把别人的账号交给它。

### 个人微信从浏览器登录

二维码交换一直可用，但它只从渠道自身的 `start()` 运行，并把二维码绘制到服务器 stdout——在任何容器部署中，这就是配置 Partner 的人无法访问的 supervisord 日志（[#951](https://github.com/HKUDS/DeepTutor/issues/951)）。现在同一交换流程也服务于 Web 应用：在 Partner 的渠道页面点击 **扫码连接**，扫码后 bot token 由服务端写入渠道配置。状态回复只说明登录是否成功，绝不透露产物内容。终端仍会打印二维码作为后备。

### 知识库可跟踪 GitHub 仓库

将仓库、分支和 glob 注册为 **GitHub 源**，其 Markdown 会被拉入知识库并按需重新同步，你关注的文档无需重新上传即可保持最新。由 [#903](https://github.com/HKUDS/DeepTutor/pull/903) 贡献；下载目标被限制在知识库的 `raw/` 目录内，否则目录树条目中的 `..` 段或绝对路径会写到——并在删除分支上删掉——基目录之外的文件。

### Antigravity CLI 加入 My Agents

Google 于六月停用 Gemini CLI，并引导用户转向 Antigravity CLI，导致使用 Google AI Pro/Ultra 或 Gemini Code Assist 计划的用户只剩下一个无 CLI 可检测的 `gemini` 后端（[#828](https://github.com/HKUDS/DeepTutor/issues/828)）。`agy` 现已成为独立后端——可连接、可在轮次中咨询、可恢复其对话。Gemini CLI 后端保留：持有 Gemini API key 的用户仍可使用，且可用的连接不会因升级而中断。

### `deeptutor doctor`

一条命令回答“此工作区是否已准备好启动会话？”——设置、提供商、依赖、端口。`--online` 还会向配置的模型提供商发送一个小请求；`--format json` 为脚本或 agent 打印同样的报告。由 [#959](https://github.com/HKUDS/DeepTutor/pull/959) 贡献。

### 容器保留你声明的可选组件

容器是一次性的，因此 `docker exec … pip install ".[partners]"` 只能存活到下一次 `compose down`（[#762](https://github.com/HKUDS/DeepTutor/issues/762)）。改为在部署上声明——`DEEPTUTOR_EXTRAS: "math-animator,partners"`，系统库用 `DEEPTUTOR_APT_PACKAGES`——由此启动的每个容器都会重新应用它们。热容器对每个依赖只付一次元数据查询，pip 缓存存放在数据卷上，缺失的 wheel 只会让该功能不可用，而不会拖垮整个部署。

### 嵌入在限流提供商下仍可完成

对低 RPM 提供商重建大型库的索引过去会耗费数小时，然后因 429 失败。三处改动：key 池在 `provider × model` 间轮换，并按 key 冷却，单个被限流的 key 不再毒化整次运行；重试预算会等待 `Retry-After`，而不是在滑动窗口上耗尽自身；进程级节流在并发重建索引间串行化“间隔加发送”，这正是手动成功的请求在应用内失败的原因。由 [#962](https://github.com/HKUDS/DeepTutor/pull/962) 贡献。

### Windows

MinerU 解析过去用平台默认编码解码子进程输出——zh-CN 安装下是 GBK——遇到第一个非 ASCII 字节即崩溃；其多线程 PDF 渲染器另有堆损坏问题。两者均已修复，渲染保护仅限 Windows（[#844](https://github.com/HKUDS/DeepTutor/pull/844)）。原子写入现在会重试杀毒软件或索引器占用目标文件导致的瞬时 `PermissionError`，代码执行在 Windows 主机上也可用（[#964](https://github.com/HKUDS/DeepTutor/pull/964)）。

### 其他

- **推理强度按对话设置。** v1.5.9 的模型级控制现在可为单个聊天覆盖（[#641](https://github.com/HKUDS/DeepTutor/issues/641)，由 [#958](https://github.com/HKUDS/DeepTutor/pull/958) 贡献）。
- **索引失败有界，不再挂起。** 接受嵌入请求却永不完成的提供商会让 executor future 永久停滞；心跳守卫现在会在有界无进展窗口后抛出异常（[#946](https://github.com/HKUDS/DeepTutor/issues/946)）。
- **MinerU 页面布局块不再作为内容索引。** 页眉、页脚和页码在入库前被过滤；无法识别的块类型会被索引而非导致整次运行失败，因此新增块类型的 MinerU 版本不会破坏索引（[#949](https://github.com/HKUDS/DeepTutor/pull/949)）。
- **语音转写接受 Chrome 录制的格式。** `audio/webm;codecs=opus` 在传输边界统一规范化一次，不再被当作未知格式拒绝（[#945](https://github.com/HKUDS/DeepTutor/issues/945)）。
- **掌握度测验卡片不再落在折叠线以下。** 查看器过去在流式输出后的滚动窗口关闭后才挂载（[#960](https://github.com/HKUDS/DeepTutor/pull/960)）；选项重复标签或答案的测验在注册时即被拒绝，而不是显示为无法作答的卡片（[#956](https://github.com/HKUDS/DeepTutor/pull/956)）。
- **学习路径保留其名称。** 三个界面各自从第一个模块推导名称，重建地图会重命名路径且三者可能不一致；现在由一个函数统一回答，推导仅作后备，绝不作为记录。
- **改变本轮操作对象的工具最先运行。** 轮次中途切换掌握度路径会让其他调用仍绑定到轮次开始时的状态；调度器现在先运行重绑定工具，再重绑定其余一切，最后运行暂停类工具。
- **本地 LightRAG 回答会引用来源**（[#754](https://github.com/HKUDS/DeepTutor/pull/754)），本地 LlamaIndex 流水线不再在导入时冻结其进度条决策（[#864](https://github.com/HKUDS/DeepTutor/pull/864)）。
- **Azure OpenAI 接受门户提供的端点。** 经典 `…/openai/deployments/<name>/chat/completions` URL 会被归约为 `/openai/v1` 接口，聊天不再在设置探测通过时返回 `404 Resource not found`。
- **Gemini 在模型支持时嵌入图片**，对不支持的模型拒绝 `contents`，而不是发送端点会拒绝的 parts（[#814](https://github.com/HKUDS/DeepTutor/issues/814)）。
- **页面可询问某项能力是否已安装。** Whisper 练习室等由插件提供的能力过去在标准安装中也会被提供，但无法兑现，轮次返回 `Unknown capability`（[#963](https://github.com/HKUDS/DeepTutor/issues/963)）。
- **独立 CLI 包声明其实际导入的依赖**（[#954](https://github.com/HKUDS/DeepTutor/pull/954)）。

## 升级说明

`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无需重建索引，无需手动迁移。

- **非管理员用户获得 Partners 页面。** 在多用户部署中，成员现在可创建和管理自己的 Partner，且与任何 Partner 的对话对其账号私密。现有 Partner 没有 `owner_id`，因此读作管理员管理——与过去完全一致——你已配置的内容不会易手。
- **渠道状态按 Partner 迁移，以复制方式。** 首次启动时，`data/partners/<channel>/` 下的状态在归属明确时复制到 `data/partners/<id>/channels/<channel>/`。旧目录树保持不动，出现坏结果可手动恢复；归属不明确的 Partner 只需重新认证一次。
- **授权现在只列出管理员管理的 Partner。** 成员自行创建的 Partner 不会出现在可指派池中。
- **容器可选组件需主动启用。** 在 Compose 文件中设置 `DEEPTUTOR_EXTRAS` 前不会有任何变化。可用 `python scripts/install_extras.py --dry-run "<name>"` 预览。
- **Gemini CLI 连接继续可用。** Antigravity 是额外后端，不是替代品。
