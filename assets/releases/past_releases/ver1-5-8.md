# DeepTutor v1.5.8 发布说明

**发布日期：** 2026.08.02

本次维护版本只解决一个问题：内存不再持续攀升。[v1.5.7](ver1-5-7.md) 源码部署在会话中途 V8 崩溃前内存已超过 14 GB，原因彼此独立——前端开发服务器的堆上限从未传到真正持有内存的进程、进程内缓存无上限、每轮对话都新建 HTTP 客户端。可直接升级，无需迁移，但源码检出的启动方式有变化。

## 新增内容

### 开发服务器其实从未设上限

`next dev` 在它自己派生的 worker 中渲染，而 argv 里的 V8 参数不会被子进程继承——所以长期使用的 `node --max-old-space-size=4096 …/next dev` 从未传到持有内存的进程。由于 `NODE_OPTIONS` 中没有上限，Next 改用总内存的 50%：24 GB 机器上即 12 GB 堆，V8 确实会尝试填满它，直到在一次标记压缩中持续 63 秒后因 `Ineffective mark-compacts near heap limit` 崩溃。`web/scripts/dev.mjs` 现在通过 `NODE_OPTIONS` 传递上限，worker 会继承该变量，Next 也会遵守——上限钳制为 4 GB，容器内按 cgroup 限制而非宿主机内存计算。

### 源码安装改为提供生产构建

从检出目录运行 `deeptutor start` 现在会先把前端构建到 `.next-deeptutor` 并提供 standalone 输出，直到输入真正变化才重新构建（指纹覆盖 `web/` 目录树、版本文件和构建时公共设置）。热重载移至 `deeptutor start --dev`，继续使用 `.next`——目录分离，两种模式运行时互不使对方的输出失效。长期运行的部署不再为开发编译器的缓存付出代价。

### 有界 LLM 客户端，不再每轮新建

聊天、研究和问答流水线每轮都会新建一个 OpenAI 兼容客户端，以及一个新的 HTTP 连接池。现在 agentic 客户端和服务层 provider 都来自事件循环本地的 LRU 池（容量 2），以绑定、模型、凭据和 base URL 为键，关闭时释放，设置变更时淘汰。只导入所选后端的 SDK。

### 有上限的缓存

知识任务日志流现在按任务限制事件数和字节数，任务结束一小时后过期，并保留一个小型完成墓碑，让迟到的订阅者仍能得知任务已完成。已完成任务表保留 256 条。LlamaIndex 索引缓存从 8 条降到 2 条，空闲 10 分钟即淘汰。书籍运行时在队列排空后释放，不再随进程常驻。

### 回收已释放的内存

一轮对话结束、书籍任务完成或知识库任务完成后，DeepTutor 会回收循环，并在 Linux 上调用 `malloc_trim`，让 glibc 归还空闲堆页，而不是保留 arena 使 RSS 看起来永远居高不下。容器和 `deeptutor start` 还会设置 `MALLOC_ARENA_MAX=2` 和更低的 trim 阈值，运维人员可自行调优覆盖。

### 一个表现为 500 的 keep-alive 竞态

`web/proxy.ts` 通过 Node 的 `http.globalAgent` 转发到后端，后者用 5 秒定时器回收空闲 socket——与 uvicorn 默认值相同。两端在同一 socket 上启动同一计时器并竞相关闭；当服务器的 FIN 落在一个连接池正同时交给新请求的 socket 上时，该请求因 `ECONNRESET` 失败，在 UI 上表现为“Failed to load sessions”。现在每次启动 uvicorn 都设置 `--timeout-keep-alive 300`，只由客户端一侧回收空闲连接。

### 其他

- `deeptutor.agents`、`deeptutor.core.agentic`、provider-core 包、文档提取器的解析库（PyMuPDF、pypdf、python-docx、openpyxl、python-pptx）以及 LLM 错误映射规则都改为首次使用时解析，而非导入时。
- `python -m deeptutor.api.run_server` 不再以 `--reload` 启动；需设置 `DEEPTUTOR_DEV_RELOAD=1`。Reload 会运行一个 supervisor 加一个 worker 并保留文件监视状态，属于开发机制。`deeptutor serve --reload` 不变。

## 升级说明

从 v1.5.7 直接升级：`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 或配置变更。

- **源码检出先构建再提供服务。** 升级后首次 `deeptutor start` 会运行 `npm run build`，耗时相应变长；后续启动复用该构建，直到源码变化。需要原来的热重载循环请用 `deeptutor start --dev`。新的 `web/.next-deeptutor/` 构建目录已加入 git 忽略。
- **`python -m deeptutor.api.run_server` 默认不再 reload。** 设置 `DEEPTUTOR_DEV_RELOAD=1` 可恢复。
