# DeepTutor v1.2.3 发布说明

**发布日期：** 2026.04.24

## 亮点

### 聊天中的文档附件
聊天现在除图片外，还接受非图片文件附件（PDF、DOCX、XLSX、PPTX）。输入框新增回形针按钮，点击打开系统文件选择器；拖拽和粘贴也从仅支持图片扩展到所有支持的文档类型。附件在待发送栏和消息历史中均渲染为带类型的预览卡片（彩色图标 + 文件名 + 大小标签）。后端新增 `document_extractor` 模块，使用 PyMuPDF / pypdf / python-docx / openpyxl / python-pptx（均为可选依赖，缺失时优雅降级）从上传的字节中提取纯文本，并注入到有效用户消息的 `[Attached Documents]` 部分，LLM 无需额外 RAG 调用即可读取文件。文件类型分类、单文件及总大小限制、重名检测由前端的 `web/lib/doc-attachments.ts` 和后端的 `DocumentValidator` 处理。

### 模型思考块展示
推理模型（DeepSeek-R1、启用扩展思考的 Claude、QwQ 等）的回复常包含 `<think>` / `<|thinking|>` 草稿块，此前被当作原始文本渲染。新增 `parseModelThinkingSegments` 解析器（`web/lib/think-segments.ts`）将助手内容拆分为交替的文本段和思考段，`AssistantResponse` 现将每个思考段渲染为可折叠的 `ModelThinkingCard`（默认折叠），用户可查看模型的思维链，而草稿块不会淹没对话。未完成（仍在流式输出）的思考块显示脉冲指示器并自动展开。

### 嵌入的三态 `send_dimensions`（#368）
部分 OpenAI 兼容的嵌入提供商拒绝 OpenAI `text-embedding-3-*` 模型所需的 `dimensions` 参数。修复分两部分：第一，适配器现在仅在模型名匹配 `text-embedding-3*` 时发送 `dimensions`（PR #368，作者 **@jefflv**）。第二，设置页、`.env` 存储（`EMBEDDING_SEND_DIMENSIONS`）和模型目录新增 **Send Dimensions** 三态开关（Auto / On / Off），让运维人员显式控制。`Auto`（默认）保留 #368 的启发式逻辑；`On` 对接受该参数的自定义模型强制发送；`Off` 无条件抑制。该开关端到端生效：目录 → `provider_runtime.ResolvedEmbeddingConfig.send_dimensions` → `OpenAICompatibleEmbeddingAdapter`。

### LLM 提供商核心重构
单体式 `factory.py` 已围绕新的 `provider_core/` 包（约 3 000 行）重写，每个提供商家族拥有独立模块：`openai_compat_provider`、`anthropic_provider`、`azure_openai_provider`、`github_copilot_provider` 和 `openai_codex_provider`，均继承自共享的 `BaseProvider`。`provider_factory.py` 从配置解析正确的运行时提供商；`factory.py` 本身从约 600 行缩减至约 490 行，改为从 `PROVIDERS` 注册表动态派生预设，不再维护硬编码字典。新增 `context_window.py` 模块暴露 `resolve_effective_context_window()`，`ContextBuilder` 据此基于模型的真实上下文窗口而非 `max_tokens` 输出上限计算历史预算，改善大窗口模型的长对话历史召回。

### Soul 模板编辑器（PR #373）
TutorBot 的 "Soul"（系统人格）现可直接在 Agents 页面编写。新的内联编辑器支持创建、预览和保存带 YAML frontmatter 的 `SOUL.md` 模板，取代此前手动编辑磁盘文件的工作流。由 **@srinivasrk** 贡献。

### Co-Writer 保存到笔记本
Co-Writer 工具栏新增 **Save to Notebook** 按钮（📓 图标）。点击打开现有的 `SaveToNotebookModal`，新增 `co_writer` 记录类型，Co-Writer 草稿与聊天、测验条目一同出现在知识页面的 Notebooks 标签页。后端：`co_writer` 已加入笔记本记录类型枚举、摘要 agent 提示词和 API Literal 类型。

### 知识库管理改进
- **拖拽上传** — 知识页面现支持将文件直接拖放到 KB 卡片（或创建表单），实时校验扩展名/大小、检测重名，并在上传开始前显示带类型的文件选择列表。
- **`/supported-file-types` 端点** — 新增 REST 端点返回服务器当前上传策略（接受的扩展名、单文件和单 PDF 大小上限），Web 客户端无需硬编码即可保持同步。
- **更丰富的 KB 卡片** — 每张卡片现显示创建/最后更新时间戳、嵌入模型名、维度、需重建索引徽章，以及索引期间的实时进度条和百分比读数。
- **删除容错（#370）** — `shutil.rmtree` 现使用 `onerror` 处理器清除只读位并重试，避免 Docker 绑定挂载和 Windows 权限错误导致 KB 卡在列表中。
- **进度持久化** — `ProgressTracker` 现在在 `kb_config.json` 条目旁写入快照文件并发出任务流事件，WebSocket 订阅者和页面刷新可恢复实时索引状态，不再依赖内存回调。KB 达到 `ready` 后，进度数据从配置中移除，使卡片看起来像稳定资源。

### 题目生成语言保真
将 Book 引擎 `_language.py` 中的语言指令系统提取为共享模块 `services/prompt/language.py`。Deep Question 的 `Generator`、`IdeaAgent` 和 `FollowupAgent` 现对其系统提示调用 `append_language_directive()`，确保测验题目、选项和追问答案遵循用户配置的语言，不再偶尔漂移为英文。

### 设置页引导重设计
**Run Tour** 按钮从页面底部移至顶部工具栏，与 **Save Draft** 和 **Apply** 并列。引导流程本身扩展为完整的保存与测试循环（Save → Diagnostics → Apply）。原底部区域替换为简洁的配置说明，解释 `model_catalog.json` 相对 `.env` 的运行时优先级。

### CLI：笔记本 `add-md` 和 `replace-md`
两个新的 `deeptutor notebook` 子命令支持直接从终端添加或替换笔记本记录中的 Markdown 内容，适用于脚本化工作流和 CI 流水线。

### Bug 修复
- **TutorBot 纯 CJK 机器人名崩溃** — 创建名称仅含非 ASCII 字符的机器人会生成空 slug，破坏 API 路由。现生成稳定的 ASCII 回退名（`bot-<hash>`），前端在创建失败时弹出错误提示而非静默失败。
- **React 19 I18nProvider 渲染期 `setState` 警告** — `i18n.init()` 此前在 `I18nProvider` 首次渲染时同步调用，触发 React 19 关于渲染阶段状态更新的警告。初始化现移至模块加载时执行；provider 主体仅通过 `useEffect` 同步 `document.documentElement.lang`。
- **技能默认关闭** — `skillsAutoMode` 现默认为 `false`，新用户不会在未主动启用前被自动技能注入困扰。
- **Moonshot 默认 Base URL** — 从 `https://api.moonshot.ai/v1` 改为 `https://api.moonshot.cn/v1`，匹配提供商当前规范端点，所有多语言 README 已同步更新。
- **版本徽章显示** — 修复 v1.2.2 合并引入的侧边栏版本徽章渲染小问题。

### 提供商注册表增强
- **`custom_anthropic`** — 新增提供商规格，用于 Anthropic API 兼容端点（如 AWS Bedrock 代理），走 Anthropic 后端而非 OpenAI 兼容后端。
- **`thinking_style`** — 新增 `ProviderSpec` 字段，允许 Volcengine 等提供商声明其扩展思考模式的信号方式。
- **别名扩展** — `lm-studio`、`anthropic-compatible`、`openai-compatible`（连字符形式）现可识别；`canonical_provider_name()` 使用 `to_snake()` 进行更稳健的规范化。
