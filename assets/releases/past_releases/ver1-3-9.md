# DeepTutor v1.3.9 发布说明

**发布日期：** 2026.05.09

v1.3.9 在 v1.3.8 多用户基础上扩展了 TutorBot 部署选项，为思考模型提供更安全的提供商路由，并优化了 Web 引导流程。新增 Zulip 和 NVIDIA NIM 支持，改进启动体验，并合入上个版本后报告的主要问题修复。

## 亮点

### TutorBot 渠道与提供商扩展

- **Zulip 现为 TutorBot 渠道** — 机器人可监听私信和 stream 话题，执行 `allow_from`，选择仅提及回复或开放 stream 回复，并将 Zulip 事件队列桥接到异步 TutorBot 总线。
- **Zulip 中数学和文件处理更完善** — LaTeX 转换为 Zulip 兼容的 KaTeX 标记，上传/下载调用支持可配置重试，附件文件名包含上传路径摘要以避免冲突。
- **Zulip 话题隔离会话** — stream 话题现纳入聊天/会话键，空话题使用稳定的 `(no topic)` 回退值。
- **TutorBot 支持 NVIDIA NIM** — `nvidia_nim` 可用于 TutorBot 提供商配置和注册表检测，包括 NIM 省略不支持 `stream_options` 的流式行为。

### 模型与运行时可靠性

- **遵循配置的上下文窗口** — 安全上限提升至 1,000,000 tokens，大模型回退仍为 65,536，显式 128K 类模型设置不再被静默截断。
- **修复 Qwen 视觉检测** — Qwen VL 模型在 DashScope、OpenAI 兼容及自定义绑定中均被视为支持视觉。
- **最小思考模式对提供商安全** — DeepSeek、DashScope、VolcEngine、BytePlus 和 MiniMax 不再收到被拒绝的顶层 `reasoning_effort=minimal`；DeepTutor 改为发送提供商特定的禁用信号。
- **跟踪 DeepSeek v4 成本** — 研究 token 计费包含 `deepseek-v4-flash` 和 `deepseek-v4-pro` 定价条目。

### Web 与 CLI 优化

- **`deeptutor start` 启动完整 Web 栈** — CLI 现委托给 `scripts/start_web.py`，一条命令即可启动后端和前端，启动器失败通过 CLI 退出码传递。
- **侧边栏引导更清晰** — 主导航图标现提供带描述和键盘焦点支持的局部化工具提示。
- **多行用户消息保持可读** — 聊天消息渲染保留 Shift+Enter 换行，修复此前被折叠为一行的代码块和结构化提示。
- **分配资源更易理解** — 模型选择摘要和只读知识库操作现为非管理员、授权范围会话提供更清晰的标签。

### 多用户与会话存储一致性

- **分配的模型选项匹配选择器契约** — 非管理员 LLM 选项现返回 profile 名称、模型名称、标签及活跃/默认元数据，与 Web 模型选择器期望的结构一致。
- **PocketBase 会话支持更多聊天流程** — 可持久化消息元数据，支持最后消息查找，消息删除同时支持 PocketBase 字符串 ID 和 SQLite 整数 ID。
- **重新生成保持存储中立** — 轮次重试逻辑可移除最后一条助手消息，无需假设底层会话存储使用整数主键。

## 测试

- 新增 Zulip 渠道覆盖：配置解析、权限检查、重复过滤、提及、stream 话题作用域、附件提取、重试行为、LaTeX 转换、输入状态、发送、上传及启动失败。
- 新增 TutorBot NVIDIA NIM 提供商测试：注册表检测、Schema 接受及流式请求兼容性。
- 新增 LLM 回归测试：Qwen 视觉能力、显式上下文窗口预算及最小思考提供商 kwargs。
- 新增 CLI 覆盖：`deeptutor start` 传递启动器退出码。
- 新增研究 token 定价覆盖：DeepSeek v4 模型条目。

## 升级说明

- 安装或刷新 `.[partners]` extra，或 `requirements/partners.txt`，以在启用 Zulip 机器人前包含新依赖 `zulip>=0.8.0,<1.0.0`。
- 使用 `site`、`email`、`apiKey`、`allowFrom` 和 `groupPolicy` 配置 Zulip 机器人；更安全的 stream 部署使用 `mention`，仅当所有 stream 消息都应到达机器人时使用 `open`。
- 若在 DeepSeek、DashScope、VolcEngine、BytePlus 或 MiniMax 中使用 `LLM_REASONING_EFFORT=minimal`，保持设置不变；v1.3.9 会将其转换为正确的提供商特定禁用载荷。
- 大型配置上下文窗口现可能被遵循而非限制在 65,536 tokens，请验证提供商限制及预期提示成本行为。
- 可选 PocketBase 部署应确保 `messages` 集合具有 `metadata_json` JSON 字段，再依赖重新生成/会话元数据一致性。
