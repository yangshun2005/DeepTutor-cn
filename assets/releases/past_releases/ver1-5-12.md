# DeepTutor v1.5.12 发布说明

**发布日期：** 2026.08.13

[v1.5.11](ver1-5-11.md) 讲的是答案生成过程中发生的事。这一版讲的是答案的素材从哪来。网页搜索层重建到一张表上——三个一直在悄悄吞掉结果的缺陷正是这样被发现的——并在其上新增了六个提供商，大多可在中国大陆访问。第六个文档解析引擎落地；轮换过凭据的 MCP 服务器现在会重连，而不是用那个恰好排除了真实原因的解释来作答。直接升级——无需迁移，无需重建索引。

## 新增内容

### 网页搜索重建，新增六个提供商

提供商列表曾被复制到七处——后端注册表、运行时配置、设置路由、CLI 向导、前端目录、i18n 和测试——彼此已经漂移；前端把 Serper 标为已弃用，后端却仍在提供它。现在七处全部派生自一张 `SEARCH_PROVIDERS` 规格表。合并过程中暴露出三个静默缺陷：Serper 的 `num` 从未传到 API，所以 `max_results` 不起作用；Serper 丢掉了代理配置；Jina 完全没有结果数量限制。

六个提供商加入这张表——**Doubao**、**Bocha**、**Zhipu**、**Firecrawl**、**Baidu Qianfan** 和 **Aliyun IQS**。它们出现在设置 → 目录 → 搜索中，凭据字段由规格派生，`deeptutor init` 也会提供。Doubao 返回答案而不只是链接；Firecrawl 增加整页提取。Baidu 以 `qianfan` 之名回归，走官方 Qianfan API——旧的 `baidu` 键保持已弃用，不再复活。

### 搜索失败不再导致整轮失败

限流、超时或主机不可达过去会终止整轮对话。现在请求会依次尝试你其他凭据完整的搜索配置，最后回退到 DuckDuckGo，并把尝试过程记录在顶层 `search_fallback` 键下，让追踪记录显示降级而不是隐藏它。代理随请求一起传递，所以从代理后面回退依然可用。

**缺少 API 密钥**被视为相反的问题，对六个新提供商仍然立即失败。其中五个托管在中国，DuckDuckGo 在这些网络上不可达——静默降级会把“你没配密钥”变成别处一个莫名其妙的超时。

### LiteParse 加入解析引擎

第六个文档解析引擎，可在设置 → 知识库中选择，与 Text-only、MinerU、Docling、markitdown 和 PyMuPDF4LLM 并列。轻量，无需下载本地模型。用 `pip install deeptutor[parse-liteparse]` 安装。

### MCP 服务器在凭据变更后重连

轮换已存储的凭据不会触动活动连接：存储的配置仍持有 `${secret:...}` 引用，指纹逐字节相同，重载差异比较便断定没有变化。现在连接按*解析后*的配置计算指纹，账户会用刚设置的密钥重连。另外，工具调用期间的传输失败——最常见的是认证——会在 SDK 自己的任务组内抛出，让调用方一直等到完整的工具超时，并报告那个已被排除的原因。现在调用期间会监视连接，模型和用户在一秒内就能得知真实错误。这些消息中的 URL 会被脱敏，因为服务器可能把凭据放在查询参数里。

### CodeBuddy 和 OrcaRouter

又两个模型提供商：**CodeBuddy/WorkBuddy**，校验 CodeBuddy SDK 认证，需要时启动浏览器登录；以及 **OrcaRouter**，一个具名的 OpenAI 兼容网关，聊天和嵌入均可用。

### Codex 保留推理强度，并能看图

托管的推理强度覆盖现在会持久化，不再在会话之间重置；OpenAI Codex 被标记为支持视觉，图像能送达它而不是被丢弃。Gemini 3 和 2.5 Pro 拒绝 `reasoning_effort="none"`，现在默认 `minimal`——这两个系列接受的最低级别。

### 其他

- **RAG 引用读取结构化载荷。** 引用提取优先使用 `ToolResult.metadata["sources"]`，而不是解析文本答案（后者通常根本得不到来源）；解析仍作为旧追踪的回退。
- **Responses 工具调用不再交叉派发。** 缺失的输出项 id 曾被填成字面量 `fc_0` 并注册为身份，于是下一个省略 id 的调用会解析到上一次调用的缓冲区，并以它的名称和参数运行。该占位符不再是别名。
- **掌握路径独立于聊天会话**，打开路径不再打扰你所在的会话。
- **聊天历史加载后停在底部**，而不是落在滚动中间。
- **助手输出能正确渲染 `**bold**`**，即使模型在标记内输出了多余空格。
- **过时的 Typer extra 已移除**，两个打包清单均已清理。

## 升级说明

`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 变更，无需重建索引，无需迁移。

- **`GET /api/v1/settings/provider-choices` 结构变了。** `search` 数组的每一项新增 `requires_api_key`、`requires_base_url`、`soft_fallback` 和 `status`，数组现在*还会*返回 `exa`、`baidu` 和 `openrouter`，`status: "deprecated"`——这是有意为之，让客户端能区分过期配置和拼错的名字。DeepTutor 自己的 UI 按 `status` 过滤；其他直接渲染该数组的消费方在同样处理之前会看到三个已弃用选项。
- **`get_providers_info()` 的条目新增 `requires_base_url`**，会出现在 `deeptutor config show` 和 `/api/v1/system` 诊断中。
- **无法识别的搜索提供商名称现在回退到 DuckDuckGo**，而不是抛错。此前只有 `exa`、`baidu` 和 `openrouter` 会被降级，其他未知名称一律抛错。显式 `none` 仍然抛错，因为那意味着搜索已关闭。
- **`get_available_providers()` 返回的比过去多。** 它过去会实例化每个提供商并吞掉凭据错误，所以实际上只报告活动提供商加上两个无需密钥的；现在报告所有凭据完整的配置。
- **Brave 在 CLI 诊断中标记为 `Brave`**，而非 `Brave Search`——UI 早已显示短名。
