# DeepTutor v1.5.14 发布说明

**发布日期：** 2026.08.19

[v1.5.13](ver1-5-13.md) 让书成为可读之物。这一版把助手放到你正在阅读的内容旁边：文档在对话旁打开，每条论断都附上出处页码。围绕它还有三项变化——DeepTutor 可通过对话自行配置；腾讯 IMA 库从只能搜索变为可浏览、可写入；笔记本获得独立控制台。直接升级——无需迁移，无需重建索引。

## 新增内容

### 沉浸式阅读——文档在对话旁打开

在能力菜单中选择 **沉浸式阅读**，打开 PDF、幻灯片或知识库已支持的任何文档。阅读器占工作区约三分之二，对话占其余部分，中间分隔条可拖动。

助手读取与你所见相同的单元——PDF 页面、幻灯片，或对无页格式按页大小划分的段落——因此回答会引用 `[p.12]`，阅读器滚动到该处并高亮论断对应的句子。选中段落即可提问，边读边高亮并附加笔记，然后带走你的标记：导出**带真实批注的 PDF**，在 Preview 或 Acrobat 中打开时高亮完整保留；或导出 Markdown 粘贴到自己的笔记中。

两项设计让它有据可依，而非仅凭自信。阅读回合保留完整聊天能力——网页搜索、代码执行、其他知识库——因为五个阅读工具是*追加*的，从不替换原有能力。并且在模型运行之前，DeepTutor 先用你的问题检索打开的文档，把最相关的结果交给模型，因此即使模型从不主动调用阅读工具，也能获得依据。这是普通检索，不是第二次 LLM 调用：不额外消耗 token，首个字输出前无延迟。

### 让 DeepTutor 自行配置

“把界面切换为中文，并用更好的 PDF 解析器”现在可以直接说，而不必去点击。一个回合可以检查安装、应用设置、安装解析引擎或下载其模型权重——在单次调用中实时跟踪日志，而非轮询——并向你索取凭据。

三条规则防止此举失控。**新模型或提供商在提交前先探测**，针对永不落盘的候选配置，因此助手不会把自己切换到不可达的服务上、在对话中途切断自己的供给。**API 密钥永不进入模型上下文**：它打开对应表单，你的浏览器直接把密钥提交到服务器。它能触碰的每个开关都是同一张表中的一行，各自标明作用域和影响，因此你会被告知某项更改是即时生效、需要重启，还是会使嵌入失效——而不是事后才发现。

### 腾讯 IMA：可浏览、可写入的库

IMA 库此前只能搜索。现在它还能回答“这里到底有什么”——知识库文件列表读取库自身的浏览 API，而不是把已连接的库报告为不可枚举；因请求预算被截断的列表会标注为下限，而非冒充总数。

在对话回合中，你可以列出库内容、读取完整来源而非检索片段、按时间搜索笔记、添加 URL 供 IMA 摄取，并写回笔记。这些工具是增量的：`rag` 仍可服务 IMA 库，因为它确实可通过 HTTP 搜索；附加 IMA 库不再牺牲网页搜索或其他知识库。

### 已连接知识库恢复可检索

v1.5.13 阻止 Book 扫描已连接知识库：扫描返回空，而“空”与“来源无相关内容”无法区分。该修复范围过宽。只有 Obsidian vault（完全无索引）和已连接的 subagent（非文档集合）真正不可达——`linked` 文件夹挂载的是别处构建的索引，LightRAG Server 和 IMA 通过 HTTP 卸载检索。这三者都被排除，导致每本书都悄悄丢弃了它们。检索现在判断的是知识库*能否被检索*，而非是否已连接。

### 笔记本获得控制台

笔记本从 Space 文档布局迁出，进入 `/notebook` 的独立全高控制台（旧链接重定向，含深链接）。记录可在笔记本间复制或移动，整个笔记本可导出为单个 Markdown 文档。

同时修复三个缺陷。并发保存可能互相覆盖；现在每个笔记本有自己的锁，每次写入都是原子的，崩溃时保留前一文件而非截断文件。文件损坏的笔记本会以标记行显示，而非从列表中消失。重命名记录曾会清除其知识库链接，因为 API 无论你是否发送都会转发每个字段。

### 设置写入不再互相覆盖

两个写入方共享 `interface.json`，彼此的锁互不覆盖。修复前实测，六次偏好保存与对话回合的六次写入竞争，所有保存全部丢失。现在两者都经过同一把锁和同一次原子替换。另外，设置端点不再写回合并默认值后的视图：更改主题曾会把当天的默认值作为显式选择冻结进你的文件，导致你悄悄停止跟随这些默认值的后续变更。

### 其他

- **能力菜单重新分组。** Chat、Quiz、Visualize、Mastery Path 和沉浸式阅读一键可达；Research 和 Solve 移至*更多能力*下。分组现在纯粹关乎菜单顺序——此前取决于能力运行在哪个引擎上，意味着不谎报引擎就无法重排菜单。
- **`write_note` 报告此前隐藏的失败。** 即使没有笔记本接受写入，也会返回记录 id，并被当作成功。
- **损坏的笔记本不再导致对话回合失败**（解析笔记本引用时），且 `/notebook/health` 恢复可达——它声明在 `/{notebook_id}` 之后，一直被其遮蔽。

## 升级说明

`pip install -U deeptutor`；Docker 用户拉取 `ghcr.io/hkuds/deeptutor:latest`。无 Schema 变更，无需重建索引，无需迁移。

- **沉浸式阅读按用户存储材料**，位于新的 `reading` 工作区目录，首次使用时创建。打开文档前不写入任何内容。
- **能力选择器外观有变。** Research 和 Solve 现在位于*更多能力*下；没有移除任何功能，正在使用其中之一的会话继续正常工作。
- **阅读无需新的 Python 依赖**（PyMuPDF 已是核心依赖），PDF 查看器随前端包发布——源码安装在下一次 `npm install` 时获取。
- **扫描版纯图像文档会被拒绝并给出说明**，而非打开为空阅读器。请先做 OCR，或在知识库中用支持 OCR 的解析引擎建立索引。
